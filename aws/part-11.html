⚡ DynamoDB — NoSQL

A fully managed key-value & document database with single-digit-millisecond latency at any scale.

Concept What is DynamoDB?

DynamoDB is a serverless NoSQL database. No servers, no patching — it scales to millions of requests per second with consistent low latency.

  • Serverless — no instances to manage.
  • Key-value & document — flexible, schemaless items.
  • Single-digit-millisecond performance at any size.
  • Built-in replication across 3 AZs; 99.999% availability with Global Tables.
📌
Use DynamoDB for high-scale, well-understood access patterns: user sessions, carts, IoT, leaderboards, event data. Use RDS when you need rich ad-hoc SQL joins.

Data model Keys & Items

A table holds items (rows); each item is a set of attributes. The primary key uniquely identifies items and drives partitioning.

Key typeMade of
Partition keyone attribute (hash) — spreads data
Composite keypartition key + sort key
aws dynamodb create-table --table-name Orders \
  --attribute-definitions \
    AttributeName=userId,AttributeType=S \
    AttributeName=orderId,AttributeType=S \
  --key-schema \
    AttributeName=userId,KeyType=HASH \
    AttributeName=orderId,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST
💡
Choose a partition key with high cardinality and even access (e.g. userId) to avoid “hot partitions” that throttle.

Query, not scan Reading & Writing

Fetch items by key with GetItem/Query. Avoid Scan (reads the whole table). For other access patterns, add secondary indexes.

# efficient: query by partition key
aws dynamodb query --table-name Orders \
  --key-condition-expression "userId = :u" \
  --expression-attribute-values '{":u":{"S":"user-123"}}'
IndexLets you query by
GSI (global)any attribute; own throughput
LSI (local)alt sort key, same partition
⚠️
DynamoDB rewards designing tables around your queries. Model access patterns first; a Scan on a big table is slow and expensive.

Pay your way Capacity Modes

ModeBest for
On-Demandunpredictable / spiky traffic
Provisionedsteady, predictable load (cheaper)

Provisioned mode uses RCUs/WCUs (read/write capacity units) and can auto-scale between bounds.

💡
Start with On-Demand while learning or for new apps. Switch to provisioned + auto-scaling once traffic is predictable to cut cost.

Power features Streams, TTL & Global Tables

  • DynamoDB Streams — a change log you can trigger Lambda from (Part 12).
  • TTL — auto-expire items by timestamp (sessions, temp data).
  • Global Tables — multi-Region, active-active replication.
  • DAX — in-memory cache for microsecond reads.
  • Transactions — all-or-nothing multi-item writes.
Streams turn data changes into events — the basis of event-driven, serverless pipelines.
📌
Streams + Lambda is a classic serverless pattern: react to every insert/update/delete without polling.
