📦 Containers — ECS, ECR & EKS

Package apps in containers and run them on AWS — with or without managing servers.

Concept Why Containers?

A container packages your app with its dependencies so it runs the same everywhere. Docker is the standard format.

  • Consistent — “works on my machine” becomes “works everywhere”.
  • Lightweight — faster and denser than full VMs.
  • Portable — same image in dev, test and prod.
  • Scalable — start many identical copies quickly.
📌
Containers sit between VMs (EC2) and functions (Lambda): more control than serverless, more efficiency than full instances.

Store your images ECR — Image Registry

ECR (Elastic Container Registry) is a private Docker image registry. Build an image, push it to ECR, then run it on ECS/EKS.

# authenticate Docker to ECR, then build & push
aws ecr get-login-password | docker login --username AWS \
  --password-stdin 123456789012.dkr.ecr.ap-south-1.amazonaws.com

docker build -t my-app .
docker tag my-app:latest $REPO/my-app:latest
docker push $REPO/my-app:latest
💡
Enable image scanning on push so ECR flags known vulnerabilities in your images before they reach production.

AWS-native ECS — Container Orchestration

ECS (Elastic Container Service) runs and manages containers. You describe a task definition; ECS schedules tasks and keeps a service at the desired count.

ConceptMeaning
Task definitionblueprint: image, CPU, memory, ports
Taska running instance of the definition
Servicekeeps N tasks running + integrates ELB
Clusterlogical group of tasks/capacity
📌
An ECS service behind an ALB gives you the same resilience as an EC2 ASG — but for containers, with rolling deployments built in.

No servers to manage Fargate — Serverless Containers

AWS Fargate runs ECS (or EKS) tasks without you managing EC2 hosts. You specify CPU/memory per task; AWS provisions the compute.

EC2 launch typeFargate
You managethe EC2 hostsnothing — just tasks
Pricingper instanceper task vCPU/mem
Best forfine control, cost tuningsimplicity, spiky load
💡
Start with Fargate: no patching or capacity planning. Move to the EC2 launch type only when you need GPU, special instances, or maximum cost control at scale.

Managed Kubernetes EKS — Kubernetes

EKS (Elastic Kubernetes Service) runs managed Kubernetes. Choose it if you already use Kubernetes or need its rich ecosystem and portability.

eksctl create cluster --name prod --fargate
kubectl get nodes
kubectl apply -f deployment.yaml
📌
EKS gives you standard Kubernetes (portable across clouds) with AWS managing the control plane. It’s more powerful but more complex than ECS.

Decision guide Choosing a Service

Match the tool to the need: Lambda for events, ECS/Fargate for services, EKS for Kubernetes shops.
💡
Most teams without an existing Kubernetes investment should pick ECS on Fargate — the simplest path to running containers in production on AWS.

Practice

  3. Decide ECS vs EKS for an app and justify the choice.
