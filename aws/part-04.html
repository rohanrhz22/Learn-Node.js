🖥️ EC2 — Virtual Servers

Launch, connect to and manage virtual machines in the cloud — the workhorse of AWS compute.

Concept What is EC2?

EC2 (Elastic Compute Cloud) provides resizable virtual servers (“instances”) you launch in minutes and pay for by the second.

  • Choose the OS via an AMI (Amazon Machine Image).
  • Choose size via an instance type (vCPU + memory).
  • Control access with security groups and key pairs.
  • Attach storage with EBS volumes (Part 5).
📌
“Elastic” = you can scale instances up, down, in or out at will — no long-term hardware commitment.

Step by step Launching an Instance

Every launch makes the same key choices, whether in the console or CLI:

AMI, instance type, network/security, and a key pair — the four core decisions of every EC2 launch.
aws ec2 run-instances \
  --image-id ami-0abcd1234 \
  --instance-type t3.micro \
  --key-name my-key \
  --security-group-ids sg-0123 \
  --subnet-id subnet-0123 \
  --tag-specifications \
    'ResourceType=instance,Tags=[{Key=Name,Value=web-1}]'
💡
Always tag instances (e.g. Name, Env). Tags drive cost reports, automation and finding things later.

Right-sizing Instance Types & Families

Instance types are grouped into families optimised for different workloads. The name encodes family, generation and size: t3.micro, m6i.large.

FamilyOptimised for
t (t3, t4g)general / burstable, cheap
m (m6i)balanced general purpose
c (c7g)compute-intensive
r / xmemory-intensive
g / pGPU / ML workloads
📌
Free-Tier eligible: t2.micro / t3.micro. Start small and resize later — you can stop an instance and change its type.

Get a shell Connecting via SSH

Use your private key to SSH into a Linux instance. The security group must allow port 22 from your IP.

chmod 400 my-key.pem
ssh -i my-key.pem ec2-user@<public-ip>

# default users by AMI:
#   Amazon Linux -> ec2-user
#   Ubuntu       -> ubuntu
⚠️
Restrict SSH (port 22) to your IP only, never 0.0.0.0/0. For keyless access, use EC2 Instance Connect or Session Manager.

Automate at boot User Data & Metadata

User data is a script that runs once at first boot — great for installing software. Instance metadata lets an instance learn about itself.

#!/bin/bash
yum update -y
yum install -y httpd
systemctl enable --now httpd
echo "Hello from $(hostname)" > /var/www/html/index.html
# from inside the instance — query metadata (IMDSv2)
TOKEN=$(curl -X PUT "http://169.254.169.254/latest/api/token" \
  -H "X-aws-ec2-metadata-token-ttl-seconds: 60")
curl -H "X-aws-ec2-metadata-token: $TOKEN" \
  http://169.254.169.254/latest/meta-data/instance-id
💡
Pass the script with --user-data file://setup.sh. User data is how Auto Scaling (Part 9) configures fresh instances automatically.

Practice

  1. Launch a t3.micro with user data that installs a web server.
  2. SSH in and confirm the web page is served.
  3. Stop the instance, change its type, and restart it.
