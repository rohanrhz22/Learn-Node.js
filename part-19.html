🛳️ Deployment: PM2, Docker & CI/CD

Take your app from “works on my machine” to running reliably in production.

Checklist Production Prep

Before deploying, get the app production-ready:

  • Set NODE_ENV=production
  • Read config from env vars, not files (Part 10)
  • Add a start script and pin Node version in package.json
  • Add a /health endpoint (Part 14)
  • Run npm audit and npm ci for reproducible installs
// package.json
{
  "engines": { "node": ">=20" },
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  }
}

Tool PM2 — Process Manager

PM2 keeps your app alive: auto-restart on crash, clustering across cores, and log management.

npm install -g pm2

pm2 start server.js --name api -i max  # cluster on all cores
pm2 logs api                            # view logs
pm2 restart api
pm2 startup && pm2 save                 # auto-start on server reboot
// ecosystem.config.js
module.exports = {
  apps: [{
    name: "api",
    script: "server.js",
    instances: "max",
    exec_mode: "cluster",
    env: { NODE_ENV: "production", PORT: 3000 },
  }],
};
💡
-i max runs one instance per CPU core and load-balances between them — instant horizontal scaling on one machine.

Tool Docker — Containerize It

Docker packages your app with its exact Node version and dependencies into an image that runs identically anywhere.

# Dockerfile
FROM node:20-alpine
WORKDIR /app

# install deps first for better layer caching
COPY package*.json ./
RUN npm ci --omit=dev

COPY . .
EXPOSE 3000
CMD ["node", "server.js"]
# .dockerignore
node_modules
.env
logs
*.log
docker build -t my-api .
docker run -p 3000:3000 --env-file .env my-api
One image runs the same on your laptop, a server, or the cloud.
📌
Copy package*.json and install before copying the rest — Docker caches that layer so rebuilds are fast.

Tool Docker Compose — Multi-Service

Real apps need a database and cache too. Compose defines and runs them together with one command.

# docker-compose.yml
services:
  api:
    build: .
    ports: ["3000:3000"]
    env_file: .env
    depends_on: [mongo, redis]

  mongo:
    image: mongo:7
    volumes: ["mongo-data:/data/db"]

  redis:
    image: redis:7

volumes:
  mongo-data:
docker compose up -d     # start everything in the background
docker compose logs -f api
docker compose down

Workflow CI/CD — Automate Everything

CI/CD automatically tests and deploys on every push. Here's a GitHub Actions pipeline:

# .github/workflows/ci.yml
name: CI
on: [push]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm test
      - run: npm audit --audit-level=high
Every push runs tests; only green builds get deployed.
⚠️
Never deploy untested code. Make passing tests a required check before any merge or deploy.
