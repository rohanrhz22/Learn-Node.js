🔐 Authentication: bcrypt & JWT

Let users sign up and log in — without ever storing a real password.

Concept Why Not Store Plain Passwords?

If your database leaks and passwords are stored as plain text, every account is compromised. The fix: store a one-way hash, never the password itself.

Hashing is one-way — you can verify a password but never reverse the hash.
⚠️
Never log, email, or store raw passwords. Hashing is mandatory, not optional.

Security Hashing with bcrypt

bcrypt adds a random salt and is deliberately slow, which makes brute-forcing expensive.

npm install bcrypt jsonwebtoken
const bcrypt = require("bcrypt");

// hashing (on signup)
const hash = await bcrypt.hash("secret123", 10); // 10 = salt rounds

// verifying (on login)
const ok = await bcrypt.compare("secret123", hash); // true / false
📌
Higher salt rounds = more secure but slower. 10–12 is a good balance for most apps.

Hands-on Signup Flow

Hash the password automatically with a Mongoose pre-save hook, so controllers never deal with raw passwords:

// src/models/userModel.js
const bcrypt = require("bcrypt");

userSchema.pre("save", async function (next) {
  if (!this.isModified("password")) return next();
  this.password = await bcrypt.hash(this.password, 10);
  next();
});

// hide the hash when sending JSON
userSchema.set("toJSON", {
  transform: (doc, ret) => { delete ret.password; return ret; },
});
// controller
exports.signup = async (req, res) => {
  const user = await User.create(req.body); // password hashed by hook
  const token = signToken(user._id);
  res.status(201).json({ user, token });
};

Concept JSON Web Tokens (JWT)

After login, the server issues a signed token. The client sends it on every request to prove who they are — no server-side session needed (stateless).

A JWT is signed with a secret, so the server can trust it without a database lookup.
// src/utils/token.js
const jwt = require("jsonwebtoken");

const signToken = (id) =>
  jwt.sign({ id }, process.env.JWT_SECRET, { expiresIn: "1d" });

module.exports = { signToken };
📌
A JWT has three parts: header.payload.signature. The payload is readable — never put secrets (like passwords) inside it.

Hands-on Login & Verifying Tokens

Login route

exports.login = async (req, res) => {
  const { email, password } = req.body;
  const user = await User.findOne({ email }).select("+password");
  if (!user || !(await bcrypt.compare(password, user.password))) {
    return res.status(401).json({ error: "Invalid credentials" });
  }
  res.json({ token: signToken(user._id) });
};

Protect middleware — verify the token

const jwt = require("jsonwebtoken");

module.exports = async (req, res, next) => {
  const header = req.headers.authorization || "";
  const token = header.startsWith("Bearer ") ? header.slice(7) : null;
  if (!token) return res.status(401).json({ error: "No token" });

  try {
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    req.user = await User.findById(decoded.id);
    next();
  } catch {
    res.status(401).json({ error: "Invalid or expired token" });
  }
};
// usage
app.get("/profile", protect, (req, res) => res.json(req.user));
💡
Return the same vague “Invalid credentials” message whether the email or password is wrong — don't reveal which.
