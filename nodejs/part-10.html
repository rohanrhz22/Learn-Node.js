🔒 Config & Security Hardening

Keep secrets out of code and shield your API from common attacks.

Concept Environment Variables

Secrets (DB URLs, JWT keys, API keys) must never live in your code or git history. Store them in the environment — different values per machine.

Config is injected at runtime, so the same code runs safely anywhere.
⚠️
Add .env to .gitignore immediately. A leaked secret in git history is compromised forever.

Setup Using dotenv

npm install dotenv
# .env  (never commit this)
PORT=3000
MONGO_URI=mongodb+srv://...
JWT_SECRET=a-long-random-string
NODE_ENV=development
// load it FIRST, before anything reads process.env
require("dotenv").config();

const port = process.env.PORT || 3000;

Validate config at startup

const required = ["MONGO_URI", "JWT_SECRET"];
for (const key of required) {
  if (!process.env[key]) {
    throw new Error(`Missing env var: ${key}`);
  }
}
💡
Commit a .env.example with empty keys so teammates know what to set, without exposing real values.

Security Securing HTTP Headers with helmet

helmet sets a dozen protective HTTP headers (XSS, clickjacking, MIME-sniffing) with one line.

npm install helmet
const helmet = require("helmet");
app.use(helmet()); // add near the top, before routes
📌
Helmet is defense-in-depth — it doesn't replace validation, but it closes many easy attack vectors for free.

Security CORS — Cross-Origin Requests

Browsers block requests from other origins by default. CORS tells the browser which front-end origins are allowed to call your API.

npm install cors
const cors = require("cors");

app.use(cors({
  origin: ["https://myapp.com"], // allowed front-ends
  credentials: true,
}));
⚠️
Avoid origin: '*' on APIs that use cookies or auth — be explicit about who can call you.

Security Rate Limiting

Stop brute-force and abuse by capping how many requests an IP can make in a window.

npm install express-rate-limit
const rateLimit = require("express-rate-limit");

const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100,                  // 100 requests per IP per window
  message: "Too many requests, please try again later.",
});

app.use("/api", limiter);

// stricter limit just for login
const loginLimiter = rateLimit({ windowMs: 15 * 60 * 1000, max: 5 });
app.use("/api/login", loginLimiter);

Reference Production Security Checklist

  • ✅ Secrets in env vars, .env git-ignored
  • ✅ helmet() enabled
  • ✅ CORS restricted to known origins
  • ✅ Rate limiting on public + auth routes
  • ✅ Input validation & sanitization (Part 12)
  • ✅ HTTPS only; NODE_ENV=production
  • ✅ Dependencies audited (npm audit)

Practice

  1. Move every secret into .env and validate them at startup.
  2. Add helmet, cors and a global rate limiter.
  3. Add a strict 5-requests limiter to your login route.
