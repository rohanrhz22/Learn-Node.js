Validation & Sanitization

Validate and sanitize input with Joi and express-validator to keep data clean.

✅ Joi🧼 Sanitize🛡️ Safe input
A

✅ Validation & Sanitization

Never trust client input — check it and clean it before it touches your logic.

Concept Why Validate Input?

Clients can send anything: missing fields, wrong types, malicious strings. Validation rejects bad shapes; sanitization cleans risky content.

Validate first to reject bad requests early, then sanitize what remains.
⚠️
Schema validation (Part 6) is your last line of defense. Validating at the route gives faster, clearer 400 errors.

Tool Validation with Joi

Joi describes the expected shape of data as a schema object, then validates against it.

npm install joi
const Joi = require("joi");

const signupSchema = Joi.object({
  name: Joi.string().min(2).max(50).required(),
  email: Joi.string().email().required(),
  age: Joi.number().integer().min(0).max(120),
  password: Joi.string().min(8).required(),
  role: Joi.string().valid("user", "admin").default("user"),
});

const { error, value } = signupSchema.validate(req.body);
if (error) {
  // error.details[0].message -> "email" must be a valid email
}
📌
Joi returns a cleaned value (with defaults applied) so you can use it directly after validating.

Pattern A Reusable Validation Middleware

Wrap Joi in middleware so any route can validate its body with one line:

// src/middleware/validate.js
module.exports = (schema) => (req, res, next) => {
  const { error, value } = schema.validate(req.body, {
    abortEarly: false,   // collect ALL errors, not just the first
    stripUnknown: true,  // drop fields not in the schema
  });
  if (error) {
    return res.status(400).json({
      errors: error.details.map((d) => d.message),
    });
  }
  req.body = value; // use the cleaned data
  next();
};
// usage
const validate = require("./middleware/validate");

app.post("/signup", validate(signupSchema), authController.signup);
💡
stripUnknown protects against mass-assignment — a user can't sneak in role: 'admin' if it's not in the schema.

Tool Alternative: express-validator

If you prefer chaining rules per field, express-validator integrates tightly with Express:

npm install express-validator
const { body, validationResult } = require("express-validator");

app.post("/signup",
  body("email").isEmail().normalizeEmail(),
  body("password").isLength({ min: 8 }),
  body("name").trim().notEmpty(),
  (req, res, next) => {
    const errors = validationResult(req);
    if (!errors.isEmpty()) {
      return res.status(400).json({ errors: errors.array() });
    }
    next();
  }
);

Security Sanitization

Sanitization neutralises dangerous input — stripping HTML/script tags and normalising values to prevent XSS and injection.

HelperEffect
trim()Remove surrounding whitespace
normalizeEmail()Canonical email form
escape()Convert <, >, & to safe entities
mongo-sanitizeStrip $ and . to block NoSQL injection
const sanitize = require("express-mongo-sanitize");
app.use(sanitize()); // blocks { "$gt": "" } style injection in queries
⚠️
Sanitize anything you'll render in a browser or put into a query. Validation checks shape; sanitization removes danger.

Practice
