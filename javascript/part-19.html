📦 Modules & Tooling

Split code into files, share packages, and bundle for the browser.

Concept Why Modules?

Modules split a program into separate files with their own scope. Each file explicitly exports what others may import.

  • Encapsulation — no accidental globals; each file has its own scope.
  • Reuse — share functions across files and projects.
  • Maintainability — small, focused files are easier to reason about.
  • Dependency clarity — imports document what each file needs.
📌
Before modules, scripts shared one global scope — a source of name clashes and bugs. ES Modules (ESM) are now the standard.

The standard ES Modules: import / export

Use export to expose values and import to consume them. Modern, browser-native and used everywhere.

// math.js
export function add(a, b) { return a + b; }
export const PI = 3.14159;
export default class Calculator {}   // one default per file

// app.js
import Calculator, { add, PI } from "./math.js";
import * as math from "./math.js";   // namespace import
add(2, 3);  math.PI;

Enable in HTML

<script type="module" src="app.js"></script>

Enable in Node

{ "type": "module" }
// in package.json
📌
Modules are deferred and run in strict mode automatically. Imports are hoisted and resolved before the module body runs.

Named vs default Import / Export Patterns

Two export styles, plus dynamic and re-exports.

// named - many per file, import by exact name:
export const a = 1; export const b = 2;
import { a, b as bee } from "./x.js";   // rename with as

// default - one per file, import with any name:
export default function () {}
import whatever from "./x.js";

// dynamic import - load on demand (returns a promise):
const mod = await import("./heavy.js");

// re-export (barrel file):
export { add } from "./math.js";
💡
Prefer named exports — they’re explicit and refactor-friendly. Use import() for lazy-loading heavy code (code splitting).

Dependencies npm & package.json

npm is the package registry and CLI. package.json records your project’s metadata, scripts and dependencies.

npm init -y               # create package.json
npm install lodash       # add a dependency
npm install -D vitest    # dev dependency
npm run dev              # run a script
npx create-vite my-app   # run a package without installing
{
  "name": "my-app",
  "type": "module",
  "scripts": { "dev": "vite", "build": "vite build" },
  "dependencies": { "lodash": "^4.17.21" }
}
⚠️
Commit package-lock.json (exact versions) but never commit node_modules/ — add it to .gitignore and run npm install to restore.

Ship to the browser Bundlers & Build Tools

Bundlers combine modules, transpile modern syntax and optimize for production.

ToolRole
Vitefast dev server + build (recommended)
esbuild / Rollupfast bundling under the hood
webpackmature, configurable bundler
Babeltranspile new JS to older JS
TypeScripttypes + compilation
A bundler resolves imports, transpiles, tree-shakes dead code and minifies output.
💡
Vite is the modern default: instant dev startup, hot-module reload, and an optimized production build with one command.

Beyond the basics The Ecosystem

Tooling that keeps codebases healthy.

  • Linters — ESLint catches bugs and enforces rules.
  • Formatters — Prettier auto-formats consistently.
  • Testing — Vitest/Jest for unit tests.
  • Type checking — TypeScript adds static types.
  • Runtimes — Node, Deno and Bun run JS outside the browser.
📌
Set up ESLint + Prettier early; they prevent whole categories of bugs and end style debates across a team.
