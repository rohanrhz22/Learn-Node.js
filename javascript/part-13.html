🚨 Error Handling

Anticipate and recover from failures so your programs degrade gracefully.

Core try / catch / finally

Wrap risky code in try; handle failures in catch; run cleanup in finally (always executes).

try {
  const data = JSON.parse(userInput);   // may throw
  process(data);
} catch (err) {
  console.error("Failed:", err.message);
} finally {
  cleanup();   // runs whether or not it threw
}
If try throws, control jumps to catch; finally runs in every case.
📌
Without try/catch, an uncaught error stops execution of the current call stack and (in the browser) logs to the console.

Signaling failure Throwing Errors

Use throw to raise an error. Always throw an Error object — not a string — so you get a message and stack trace.

function divide(a, b) {
  if (b === 0) {
    throw new Error("Cannot divide by zero");
  }
  return a / b;
}

try {
  divide(10, 0);
} catch (err) {
  err.message;   // "Cannot divide by zero"
  err.stack;     // call stack trace
}
⚠️
Avoid throw "text". A thrown string has no stack or name — always throw new Error(...).

Specific failures Built-in Error Types

JavaScript has several built-in error subclasses that signal the kind of problem.

TypeThrown when
TypeErrorvalue is the wrong type / null access
ReferenceErrorundeclared variable used
SyntaxErrorinvalid code / bad JSON
RangeErrorvalue out of allowed range
Errorgeneric base class
try { null.x; }
catch (e) { e instanceof TypeError; }   // true
💡
Use instanceof in catch to branch on error type and respond differently to each.

Domain errors Custom Error Classes

Extend Error to create meaningful, catchable error types for your application.

class ValidationError extends Error {
  constructor(field, message) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

try {
  throw new ValidationError("email", "Invalid email");
} catch (err) {
  if (err instanceof ValidationError) {
    console.log(err.field, err.message);  // "email" ...
  } else {
    throw err;   // re-throw what you can't handle
  }
}
📌
Set this.name and add custom fields (field, statusCode) so handlers higher up can react precisely.

Promises & await Errors in Async Code

Async errors need different handling — a preview of Parts 14–15.

// Promise: use .catch()
fetch("/api")
  .then(r => r.json())
  .catch(err => console.error(err));

// async/await: use try/catch
async function load() {
  try {
    const res = await fetch("/api");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } catch (err) {
    console.error("Load failed:", err);
  }
}
⚠️
A plain try/catch cannot catch errors from a non-awaited promise or an async callback — you must await or use .catch().

Guidelines Best Practices

  • Fail fast — validate inputs and throw early with clear messages.
  • Catch specifically — handle what you can; re-throw the rest.
  • Never swallow — an empty catch {} hides bugs.
  • Clean up in finally — close files, release locks, hide spinners.
  • Use custom errors — for predictable, branchable handling.
💡
Add a global safety net: window.onerror / unhandledrejection in the browser, process.on('uncaughtException') in Node.
