🌐 async / await & Fetch

Write asynchronous code that reads top-to-bottom — and call real APIs.

Sync-looking async async / await

async functions always return a Promise. await pauses inside them until a promise settles — turning chains into flat, readable code.

// promise chain:
function load() {
  return fetch("/api").then(r => r.json());
}

// same thing with async/await:
async function load() {
  const res = await fetch("/api");
  const data = await res.json();
  return data;   // wrapped in a Promise automatically
}

load().then(data => console.log(data));
await suspends the async function without blocking the thread; other code keeps running.
📌
await only works inside an async function (or at the top level of a module). It unwraps the resolved value for you.

Failures Error Handling with try/catch

With async/await you use ordinary try/catch — the same tool as synchronous code.

async function getUser(id) {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) {
      throw new Error(`HTTP ${res.status}`);
    }
    return await res.json();
  } catch (err) {
    console.error("getUser failed:", err.message);
    throw err;   // re-throw for the caller to handle
  }
}
⚠️
fetch only rejects on network failure — a 404 or 500 still resolves. Always check res.ok and throw yourself.

HTTP requests The Fetch API

fetch is the built-in way to make HTTP requests. It returns a promise resolving to a Response.

// GET + parse JSON
const res = await fetch("/api/items");
const items = await res.json();

// POST with a JSON body
const res2 = await fetch("/api/items", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ name: "Widget" })
});

// other response readers:
await res.text();  await res.blob();
💡
Set headers and JSON.stringify the body for JSON POSTs. Read the response with .json(), .text() or .blob().

Performance Parallel vs Sequential Awaits

Awaiting one after another is slow when requests are independent. Kick them off together with Promise.all.

// SLOW - 2s total (sequential):
const a = await fetchA();   // 1s
const b = await fetchB();   // 1s

// FAST - 1s total (parallel):
const [a, b] = await Promise.all([fetchA(), fetchB()]);
⚠️
Only sequence awaits when the second depends on the first. Independent requests should run in parallel with Promise.all.

Sequencing carefully Awaiting in Loops

Combine await with array methods thoughtfully — forEach does not await.

// sequential: one at a time (for...of awaits)
for (const id of ids) {
  const item = await fetchItem(id);
  console.log(item);
}

// parallel: map to promises, then await all
const items = await Promise.all(ids.map(id => fetchItem(id)));

// BUG: forEach ignores the returned promises
ids.forEach(async id => { await fetchItem(id); }); // don't
📌
array.forEach(async ...) fires all callbacks but doesn’t wait. Use for...of for sequencing or Promise.all(map(...)) for parallel.

Putting it together Real-World Patterns

A robust fetch with timeout, status check and typed errors.

async function apiGet(url, { timeout = 5000 } = {}) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), timeout);
  try {
    const res = await fetch(url, { signal: controller.signal });
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return await res.json();
  } finally {
    clearTimeout(timer);
  }
}

const data = await apiGet("/api/products", { timeout: 3000 });
💡
AbortController cancels a fetch — essential for timeouts and for aborting stale requests in search-as-you-type UIs.
