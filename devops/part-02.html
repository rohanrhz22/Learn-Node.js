🐧 Linux & the Command Line

Almost every server, container and CI runner is Linux. Get fluent in the shell you'll use daily.

Foundation Why Linux for DevOps?

Servers, containers and cloud instances overwhelmingly run Linux. The shell (commonly Bash) is how you inspect, configure and automate them.

  • Free & open — runs everywhere, no licence cost.
  • Scriptable — anything you do by hand can be automated.
  • Lightweight — ideal for containers and servers.
  • Ubiquitous — the same skills apply across every cloud.
📌
A shell is a program that reads your commands and runs them. The prompt usually ends in $ for a normal user or # for root.

Everything is a file The Filesystem

Linux organises everything under a single root /. Key directories:

PathWhat lives there
/etcConfiguration files
/var/logLog files
/homeUser home directories
/usr/binInstalled programs
/tmpTemporary files
/optOptional / third-party software
💡
Absolute paths start at / (e.g. /etc/hosts). Relative paths are from where you are now (./script.sh, ../logs).

Core commands Navigating & Working with Files

The handful of commands you'll use constantly:

pwd                 # print working directory
ls -lah             # list all files, long form, human sizes
cd /var/log         # change directory
cat app.log         # print a file
less app.log        # scroll a file (q to quit)
tail -f app.log     # follow new log lines live
grep ERROR app.log  # search inside files
find / -name "*.conf"   # find files by name
cp a.txt b.txt      # copy
mv b.txt c.txt      # move / rename
rm c.txt            # delete
mkdir -p data/raw   # make nested dirs
💡
Pipe (|) sends one command's output into another: cat app.log | grep ERROR | wc -l counts error lines.

Who can do what Users & Permissions

Every file has an owner, a group, and permissions for user / group / others: read (r=4), write (w=2), execute (x=1).

ls -l deploy.sh
# -rwxr-xr-- 1 alice devops 320 Jun 30 deploy.sh

chmod 750 deploy.sh   # rwx for owner, rx for group, none for others
chmod +x deploy.sh    # make executable
chown alice:devops deploy.sh   # set owner:group
sudo systemctl restart nginx   # run a command as root
chmod 754 — numeric permissions decode to rwx triplets.
⚠️
Use sudo deliberately. Running everything as root is how a small typo (rm -rf /) becomes a disaster.

Running systems Processes & Packages

Inspect what's running and install software:

ps aux | grep nginx    # find a running process
top                    # live process / CPU / memory view
kill -9 1234           # force-stop process with PID 1234
systemctl status nginx # service state (running/failed)
journalctl -u nginx    # logs for a service

# Install packages (Debian/Ubuntu)
sudo apt update && sudo apt install -y htop
# Red Hat / Amazon Linux
sudo yum install -y htop
📌
Environment variables configure programs: export ENV=prod then echo $ENV. They're central to 12-factor apps and containers.

Practice

  1. Use find + grep to locate every file under /etc containing the word “port”.
  2. Create a script file, chmod +x it, and run it with ./.
  3. Tail a log with tail -f while triggering activity in another terminal.
