Performance Optimization

memo, useMemo, useCallback and avoiding re-renders.

⚡ memo🧠 useMemo🔗 useCallback
A

⚡ Performance Optimization

Re-render less — memoize components, values and callbacks.

Concept Why Re-renders Happen

A component re-renders when its state or props change — and when it re-renders, all its children re-render by default, even if their props didn't change.

Most re-renders are cheap. Optimize only the ones that are measurably slow.
⚠️
Premature optimization adds complexity. Reach for these tools only after you've measured a real problem.

Skip child renders React.memo

React.memo wraps a component so it skips re-rendering when its props are unchanged (shallow comparison).

const ExpensiveList = React.memo(function ExpensiveList({ items }) {
  return <ul>{items.map((i) => <li key={i.id}>{i.name}</li>)}</ul>;
});

// re-renders only when `items` actually changes
📌
Memoization helps most for components that are expensive to render or render very often with the same props.

Compute once useMemo — cache a value

useMemo caches the result of an expensive calculation, recomputing only when its dependencies change.

const sorted = useMemo(() => {
  console.log("sorting...");          // runs only when items change
  return [...items].sort((a, b) => a.price - b.price);
}, [items]);
💡
Use useMemo for genuinely costly work (sorting/filtering big lists) or to keep an object/array reference stable across renders.

Stable refs useCallback — cache a function

useCallback returns a memoized function. It matters when passing callbacks to memo-wrapped children or to effect dependencies.

const handleAdd = useCallback((text) => {
  setTodos((prev) => [...prev, { id: Date.now(), text }]);
}, []);   // same function reference across renders

// without useCallback, a new function each render
// would defeat React.memo on the child receiving it
useMemo caches a value; useCallback caches a function (useCallback(fn,deps) ≈ useMemo(()=>fn,deps)).

Reconciliation Lists & Stable Keys

Stable keys (Part 5) are themselves a performance feature — they let React reuse DOM nodes instead of recreating them.

// ✅ stable id keys -> React reuses rows
{rows.map((r) => <Row key={r.id} {...r} />)}

// ❌ index keys -> reorders cause re-mounts & lost state
⚠️
Index keys not only cause bugs but also hurt performance when lists reorder, by forcing unnecessary re-mounts.

Discipline Measure Before Optimizing

Use real tools to find actual bottlenecks instead of guessing.

  • React DevTools Profiler — see which components render and how long they take.
  • Highlight updates — visually spot components re-rendering too often.
  • <Profiler> API — programmatic timing in code.
  • Often the fix is restructuring (lift state down, split components) — not memo everywhere.
💡
Rule of thumb: write clear code first, profile, then memoize the specific hot spots you find.

Practice

  1. Wrap an expensive list in React.memo and confirm fewer renders in the Profiler.
  2. Memoize a sorted/filtered array with useMemo.
  3. Pass a useCallback handler to a memoized child and verify it doesn't re-render.
