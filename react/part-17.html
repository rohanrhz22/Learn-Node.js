📡 Data Fetching with React Query

Treat server data as a cache, not as local state.

Concept Server State is Different

Data from a server isn't really 'your' state — it lives elsewhere, can go stale, and is shared. Storing it in useState means hand-writing caching, refetching and dedup. TanStack Query (React Query) handles all of that.

Hand-rolled useEffectReact Query
Manual loading/errorAutomatic states
No cachingSmart cache by key
Refetch by handAuto refetch & background updates
Duplicate requestsDeduped automatically
📌
Rule of thumb: client state → useState/Zustand; server state → React Query.

Provider Setup

Install and wrap your app in a QueryClientProvider.

npm install @tanstack/react-query
import { QueryClient, QueryClientProvider } from "@tanstack/react-query";

const queryClient = new QueryClient();

<QueryClientProvider client={queryClient}>
  <App />
</QueryClientProvider>
💡
Add the @tanstack/react-query-devtools panel to inspect every query's cache and status in dev.

Fetch useQuery — reading data

Give a unique queryKey and a queryFn. React Query manages loading, error, caching and refetching.

import { useQuery } from "@tanstack/react-query";

function Users() {
  const { data, isLoading, error } = useQuery({
    queryKey: ["users"],
    queryFn: () => fetch("/api/users").then((r) => r.json()),
  });

  if (isLoading) return <Spinner />;
  if (error) return <p>Error: {error.message}</p>;
  return <ul>{data.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}
Same key across components shares one cache entry and one request.

Mutate useMutation — writing data

Use useMutation for create/update/delete. It tracks isPending and success/error for you.

import { useMutation } from "@tanstack/react-query";

const addUser = useMutation({
  mutationFn: (user) =>
    fetch("/api/users", { method: "POST", body: JSON.stringify(user) }),
  onSuccess: () => {
    queryClient.invalidateQueries({ queryKey: ["users"] });
  },
});

<button onClick={() => addUser.mutate({ name: "Asha" })}>Add</button>
📌
Mutations don't auto-refetch. You tell React Query what changed by invalidating affected queries.

Stay fresh Cache Invalidation

After a mutation, invalidate related queries so React Query refetches the latest data.

// mark "users" stale -> triggers a background refetch
queryClient.invalidateQueries({ queryKey: ["users"] });

// query keys can include variables:
useQuery({
  queryKey: ["user", id],          // separate cache per id
  queryFn: () => getUser(id),
});
💡
Structured query keys (["user", id]) let you invalidate broadly (['user']) or narrowly.

Built-in Power Features

You get these essentially for free:

  • Background refetching — on window focus, reconnect, or interval.
  • Stale-while-revalidate — show cached data instantly, refresh behind the scenes.
  • Pagination & infinite scroll — useInfiniteQuery.
  • Optimistic updates — update UI before the server confirms.
  • Retries — failed requests retry with backoff automatically.
📌
React Query often replaces a big chunk of global state — much 'global state' is really just cached server data.
