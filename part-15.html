⚡ Events, Workers & Child Processes

Use every CPU core and react to things as they happen.

Concept EventEmitter — Node's Pub/Sub

Much of Node is built on events. EventEmitter lets one part of your app emit a named event and others react to it — decoupling producers from consumers.

One emitted event can trigger many independent listeners.
const EventEmitter = require("events");
const bus = new EventEmitter();

bus.on("order:created", (order) => console.log("Email sent for", order.id));
bus.on("order:created", (order) => console.log("Invoice generated"));

bus.emit("order:created", { id: 42 });
📌
Events keep modules loosely coupled — the order code doesn't need to know about email or invoicing.

Concept The Single-Thread Limit

Node runs your JavaScript on one thread. Async I/O is fine, but a heavy CPU task (image processing, big loops) blocks everything.

// BAD: this freezes the whole server while it runs
app.get("/slow", (req, res) => {
  let total = 0;
  for (let i = 0; i < 1e10; i++) total += i; // CPU-bound, blocks event loop
  res.json({ total });
});
⚠️
CPU-heavy work on the main thread makes every other request wait. Offload it to a worker or child process.

Tool Worker Threads

Worker threads run JavaScript in parallel on other cores — ideal for CPU-bound work while keeping the main thread responsive.

// worker.js
const { parentPort, workerData } = require("worker_threads");

let total = 0;
for (let i = 0; i < workerData.n; i++) total += i;
parentPort.postMessage(total);
// main app
const { Worker } = require("worker_threads");

app.get("/sum", (req, res) => {
  const worker = new Worker("./worker.js", { workerData: { n: 1e10 } });
  worker.on("message", (total) => res.json({ total })); // non-blocking!
  worker.on("error", (err) => res.status(500).json({ error: err.message }));
});
💡
Workers share memory efficiently and are the modern choice for CPU work inside one Node process.

Tool Child Processes

Child processes run separate programs — another script, a shell command, or a different language entirely.

const { exec, spawn } = require("child_process");

// exec: buffer the full output (small results)
exec("node --version", (err, stdout) => console.log(stdout.trim()));

// spawn: stream output (large/continuous results)
const ls = spawn("ls", ["-la"]);
ls.stdout.on("data", (data) => console.log(data.toString()));
MethodBest for
execShort commands, small output
spawnStreaming / large output
forkSpawning another Node script with messaging

Scaling Cluster — Use Every Core

The cluster module forks your server across all CPU cores, sharing one port — multiplying throughput.

const cluster = require("cluster");
const os = require("os");

if (cluster.isPrimary) {
  os.cpus().forEach(() => cluster.fork()); // one worker per core
  cluster.on("exit", () => cluster.fork()); // restart if one dies
} else {
  require("./server"); // each worker runs the app
}
📌
In practice a process manager like PM2 (Part 19) does clustering for you with pm2 start app.js -i max.
