🛡️ Constraints & Keys

Let the database guarantee your data is always valid and related correctly.

Concept Why Constraints Matter

Constraints are rules the database enforces on every write. They make invalid data impossible — a far stronger guarantee than checks in application code.

  • Integrity — no orphaned or duplicate rows.
  • Trust — every reader can rely on the rules.
  • Central — defined once, applied to all clients.
📌
Application validation can be bypassed or have bugs; a database constraint cannot be violated, no matter who writes the data.

Identity Primary Keys

A primary key uniquely identifies each row. It is UNIQUE + NOT NULL and is automatically indexed.

CREATE TABLE customers (
    id    integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email text NOT NULL
);

-- composite key: unique combination of two columns
CREATE TABLE enrollments (
    student_id integer,
    course_id  integer,
    PRIMARY KEY (student_id, course_id)
);
💡
Every table should have a primary key. A surrogate id (identity/serial) is the common, dependable choice.

Relationships Foreign Keys

A foreign key forces a column to reference an existing row in another table — this is what makes relationships trustworthy.

CREATE TABLE orders (
    id          integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    customer_id integer NOT NULL REFERENCES customers(id),
    amount      numeric NOT NULL
);
A foreign key rejects any order whose customer_id has no matching customer.
⚠️
Insert an order with a customer_id that doesn’t exist and Postgres raises a foreign key violation — no orphan rows.

ON DELETE / UPDATE Referential Actions

Decide what happens to child rows when a parent is deleted or its key changes.

ActionEffect on child rows
RESTRICT / NO ACTIONblock the delete (default)
CASCADEdelete/update children too
SET NULLset the FK column to NULL
SET DEFAULTset the FK to its default
CREATE TABLE order_items (
    id       integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    order_id integer REFERENCES orders(id) ON DELETE CASCADE
);
💡
ON DELETE CASCADE is handy for owned children (an order’s items). Use it carefully — deleting a parent silently removes its children.

Value rules UNIQUE & CHECK

UNIQUE forbids duplicate values; CHECK enforces an arbitrary boolean condition per row.

CREATE TABLE accounts (
    id       integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email    text UNIQUE NOT NULL,
    username text UNIQUE NOT NULL,
    balance  numeric NOT NULL DEFAULT 0 CHECK (balance >= 0),
    age      integer CHECK (age BETWEEN 13 AND 120),
    -- multi-column check:
    CONSTRAINT valid_range CHECK (start_date < end_date)
);
📌
Name constraints (CONSTRAINT valid_range ...) so error messages and ALTER TABLE are clear.

Column rules NOT NULL & DEFAULT Recap

The simplest, most-used constraints — worth combining deliberately on every column.

ALTER TABLE customers
    ADD COLUMN status text NOT NULL DEFAULT 'active'
        CHECK (status IN ('active','suspended','closed'));
💡
A CHECK (col IN (...)) is a lightweight “enum”. Postgres also has real ENUM types (Part 11) for fixed value sets.
