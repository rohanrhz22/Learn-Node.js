🧮 Filtering & Operators

Select exactly the rows you want with WHERE and its operators.

Core The WHERE Clause

WHERE keeps only the rows for which a condition is true. It runs after FROM and before ORDER BY.

SELECT name, price FROM products
WHERE price < 50;
Each row is tested; only rows where the condition is TRUE survive.
📌
A row is dropped if the condition is false or NULL — an important subtlety covered below.

Logic Combining Conditions

Build complex filters with AND, OR and NOT. Use parentheses to make precedence explicit.

SELECT * FROM products
WHERE (category = 'electronics' OR category = 'office')
  AND price < 100
  AND in_stock = true;
💡
AND binds tighter than OR. When you mix them, wrap the OR group in parentheses so it means what you intend.

Text search Pattern Matching with LIKE

LIKE matches text patterns: % is “any run of characters,” _ is “any single character.” ILIKE is case-insensitive.

SELECT * FROM users WHERE email LIKE '%@gmail.com';  -- ends with
SELECT * FROM users WHERE name ILIKE 'an%';          -- starts An/an
SELECT * FROM products WHERE sku LIKE 'A_-1';        -- A?-1
PatternMatches
'a%'starts with a
'%a'ends with a
'%a%'contains a
'a_c'a, any char, c
📌
For fuzzy/full-text search at scale, use Postgres full-text search or pg_trgm (Part 18) — LIKE '%x%' can’t use a plain index.

Sets & ranges IN & BETWEEN

IN matches any value in a list; BETWEEN matches an inclusive range — both are shorthands for long OR chains.

SELECT * FROM orders
WHERE status IN ('paid', 'shipped', 'delivered');

SELECT * FROM events
WHERE created_at BETWEEN '2026-01-01' AND '2026-03-31';

SELECT * FROM products WHERE category NOT IN ('toys');
💡
BETWEEN a AND b is inclusive of both ends. For timestamps, prefer >= start AND < end to avoid edge surprises.

Three-valued logic Working with NULL

NULL means “unknown,” not zero or empty string. Comparisons with it yield NULL, never true — so use IS NULL.

SELECT * FROM users WHERE phone IS NULL;      -- correct
SELECT * FROM users WHERE phone = NULL;       -- WRONG: matches nothing

-- substitute a fallback value:
SELECT name, COALESCE(phone, 'no phone') AS phone FROM users;
 price = NULL   →  NULL  (not true!)
 NULL = NULL    →  NULL
 NULL IS NULL   →  true
⚠️
Never use = NULL or <> NULL. Always IS NULL / IS NOT NULL. COALESCE returns the first non-null argument.
