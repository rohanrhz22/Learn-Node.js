📦 JSON & Full-Text Search

Treat PostgreSQL as a document store and a search engine — no extra services needed.

Choosing json vs jsonb

PostgreSQL has two JSON types. Use jsonb almost always.

jsonjsonb
Storageexact text copydecomposed binary
Whitespace/keyspreserved/dups keptnormalized
Read speedre-parsesfast
Indexablenoyes (GIN)
CREATE TABLE events (
    id   serial PRIMARY KEY,
    body jsonb NOT NULL
);
📌
jsonb loses insignificant whitespace and key order but gains operators and indexing — the right default for storing documents.

Operators Accessing JSON

Navigate JSON with arrow operators. -> keeps JSON; ->> returns text.

-- body = {"user":{"name":"Ada"},"tags":["sql","db"]}
SELECT body -> 'user'             AS user_json,    -- {"name":"Ada"}
       body -> 'user' ->> 'name'  AS name,         -- Ada (text)
       body -> 'tags' ->> 0       AS first_tag,     -- sql
       body #>> '{user,name}'     AS deep_name      -- Ada (path)
FROM events;
OperatorMeaning
->get field/element as JSON
->>get field/element as text
#> / #>>get by path (JSON / text)
💡
Cast extracted text to compare numerically: (body->>'age')::int > 18.

Filtering Querying & Containment

The @> “contains” operator and ? “has key” are the workhorses of JSONB querying — and they’re index-accelerated.

-- rows whose body contains this fragment:
SELECT * FROM events WHERE body @> '{"user":{"name":"Ada"}}';

-- rows whose top-level object has a 'tags' key:
SELECT * FROM events WHERE body ? 'tags';

-- rows where the tags array contains 'sql':
SELECT * FROM events WHERE body -> 'tags' ? 'sql';
📌
@> tests deep containment; ?, ?|, ?& test key existence (any/all). All can use a GIN index.

Mutation Building & Modifying JSON

Construct JSON with functions and update parts of a document with jsonb_set.

SELECT jsonb_build_object('id', 1, 'ok', true);   -- {"id":1,"ok":true}

UPDATE events
SET body = jsonb_set(body, '{user,name}', '"Grace"')
WHERE id = 1;

UPDATE events SET body = body || '{"seen":true}';  -- merge/add key
UPDATE events SET body = body - 'seen';            -- remove key
💡
|| merges objects (and appends arrays); - deletes a key. jsonb_array_elements() expands an array into rows.

Performance Indexing JSONB with GIN

A GIN index makes containment and key queries fast even over millions of documents.

CREATE INDEX idx_events_body ON events USING GIN (body);

-- faster, smaller index if you only use @> :
CREATE INDEX idx_events_body_ops
ON events USING GIN (body jsonb_path_ops);
📌
jsonb_path_ops supports only @> but is smaller and faster than the default. Add a B-tree on a frequently-filtered extracted field for equality lookups.

Native search Full-Text Search

PostgreSQL searches natural-language text with tsvector (parsed document) and tsquery (search terms), matched by @@.

SELECT title
FROM articles
WHERE to_tsvector('english', title || ' ' || body)
      @@ to_tsquery('english', 'postgres & index');

-- index it for speed (generated column + GIN):
ALTER TABLE articles ADD COLUMN search tsvector
  GENERATED ALWAYS AS (to_tsvector('english', title)) STORED;
CREATE INDEX idx_articles_search ON articles USING GIN (search);
💡
Full-text search handles stemming (“running”≈“run”) and ranking (ts_rank). For typo/fuzzy matching, add the pg_trgm extension.
