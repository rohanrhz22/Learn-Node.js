🎯 Triggers

Run a function automatically whenever rows are inserted, updated or deleted.

Concept What is a Trigger?

A trigger binds a function to a table event. PostgreSQL fires it automatically on INSERT, UPDATE, DELETE or TRUNCATE — no app code required.

BEFORE triggers can alter or veto the row; AFTER triggers react once the change is done.
TimingUse for
BEFOREvalidate or modify the row
AFTERcascade effects, audit logs
INSTEAD OFmake a view writable
📌
Row-level triggers (FOR EACH ROW) fire once per affected row; statement-level (FOR EACH STATEMENT) fire once per statement.

The handler Trigger Functions

A trigger calls a special function that RETURNS trigger. Inside it you get NEW (the incoming row) and OLD (the previous row).

CREATE OR REPLACE FUNCTION set_updated_at()
RETURNS trigger
LANGUAGE plpgsql AS $$
BEGIN
    NEW.updated_at := now();   -- modify the row before it's written
    RETURN NEW;                -- return it to proceed
END;
$$;
VariableAvailable in
NEWINSERT, UPDATE
OLDUPDATE, DELETE
TG_OPoperation name (e.g. 'UPDATE')
⚠️
In a BEFORE trigger, RETURN NULL cancels the operation for that row. Always RETURN NEW (or OLD for DELETE) to let it proceed.

Wiring it up CREATE TRIGGER

Attach the function to a table, choosing the timing and events.

CREATE TRIGGER trg_set_updated
BEFORE UPDATE ON products
FOR EACH ROW
EXECUTE FUNCTION set_updated_at();

-- only when a specific column changes:
CREATE TRIGGER trg_price_change
AFTER UPDATE OF price ON products
FOR EACH ROW
WHEN (OLD.price IS DISTINCT FROM NEW.price)
EXECUTE FUNCTION log_price_change();
💡
The WHEN clause and UPDATE OF column keep triggers from firing needlessly — good for performance.

Real use Audit Log Example

A classic pattern: record every change to a sensitive table in an audit table.

CREATE TABLE audit_log (
    id serial PRIMARY KEY, table_name text, op text,
    row_id int, changed_at timestamptz DEFAULT now()
);

CREATE OR REPLACE FUNCTION audit_orders()
RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN
    INSERT INTO audit_log(table_name, op, row_id)
    VALUES ('orders', TG_OP, COALESCE(NEW.id, OLD.id));
    RETURN COALESCE(NEW, OLD);
END;
$$;

CREATE TRIGGER trg_audit AFTER INSERT OR UPDATE OR DELETE
ON orders FOR EACH ROW EXECUTE FUNCTION audit_orders();
📌
COALESCE(NEW, OLD) works for all three operations — NEW is NULL on DELETE, OLD is NULL on INSERT.

Common recipe Auto-Maintaining Timestamps

The most common trigger of all: keep an updated_at column fresh on every update, automatically.

ALTER TABLE products ADD COLUMN updated_at timestamptz DEFAULT now();

CREATE TRIGGER trg_touch
BEFORE UPDATE ON products
FOR EACH ROW EXECUTE FUNCTION set_updated_at();   -- defined earlier

UPDATE products SET price = 9.99 WHERE id = 1;
-- updated_at is now set without the app doing anything
💡
Reuse one generic set_updated_at() function across many tables — just attach a trigger to each.

Cautions When Not to Use Triggers

Triggers are powerful but invisible — logic runs without an obvious call site.

  • Hard to debug — effects happen “magically” far from the SQL you ran.
  • Performance — row triggers run per row; heavy logic slows bulk writes.
  • Hidden cascades — a trigger that writes another table can fire its triggers.
⚠️
Prefer constraints for validation and application code for business logic; reserve triggers for cross-cutting concerns like auditing and timestamps.
