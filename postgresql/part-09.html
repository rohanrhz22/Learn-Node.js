🪆 Subqueries & CTEs

Nest queries inside queries and structure complex logic with WITH.

One value Scalar Subqueries

A subquery is a query inside another query. A scalar one returns a single value you can use like a constant.

SELECT name, price,
       price - (SELECT AVG(price) FROM products) AS diff_from_avg
FROM products;
📌
The inner query runs and produces one number; each outer row compares its price to that average.

Filtering by a set Subqueries in WHERE

Use a subquery with IN, EXISTS, or a comparison to filter against another query’s results.

-- customers who have placed at least one order:
SELECT * FROM customers
WHERE id IN (SELECT customer_id FROM orders);

-- products priced above the average:
SELECT * FROM products
WHERE price > (SELECT AVG(price) FROM products);
💡
IN (subquery) is readable, but EXISTS is often faster and handles NULLs better — see the next card.

Row-by-row Correlated Subqueries & EXISTS

A correlated subquery references the outer row, so it re-evaluates per row. EXISTS just checks whether any matching row exists.

-- customers who have NO orders:
SELECT c.name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.customer_id = c.id
);
EXISTS stops at the first match, making it efficient for “has any / has none” checks.
📌
SELECT 1 inside EXISTS is convention — the actual columns are ignored, only row existence matters.

Derived tables Subqueries in FROM

A subquery in FROM acts as a temporary table (a “derived table”). It must be given an alias.

SELECT category, avg_price
FROM (
    SELECT category, AVG(price) AS avg_price
    FROM products
    GROUP BY category
) AS summary
WHERE avg_price > 100;
💡
Derived tables let you filter on an aggregate without HAVING, or build multi-step transformations — though CTEs are usually clearer.

Readable building blocks CTEs with WITH

A Common Table Expression names a subquery up front, so complex queries read top-to-bottom like steps.

WITH paid_orders AS (
    SELECT * FROM orders WHERE status = 'paid'
),
totals AS (
    SELECT customer_id, SUM(amount) AS spent
    FROM paid_orders
    GROUP BY customer_id
)
SELECT c.name, t.spent
FROM totals t
JOIN customers c ON c.id = t.customer_id
WHERE t.spent > 500;
💡
CTEs are great for readability and can be referenced multiple times in the same query. Chain several with commas.

Hierarchies & graphs Recursive CTEs

WITH RECURSIVE repeatedly references itself — ideal for trees, org charts and graph traversal.

WITH RECURSIVE subordinates AS (
    SELECT id, name, manager_id          -- base case: the CEO
    FROM employees WHERE manager_id IS NULL
  UNION ALL
    SELECT e.id, e.name, e.manager_id    -- recursive step
    FROM employees e
    JOIN subordinates s ON e.manager_id = s.id
)
SELECT * FROM subordinates;
The recursive part keeps joining new children until no more rows are produced.
⚠️
Always ensure recursion terminates — cyclic data can loop forever. A depth counter or UNION (de-dupe) can guard against it.
