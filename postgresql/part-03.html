✏️ Inserting, Updating & Deleting

The three data-modifying statements — plus RETURNING and upserts.

Create INSERT — Adding Rows

Use INSERT INTO ... VALUES ... to add rows. Always list the columns explicitly so the query keeps working if the table changes.

INSERT INTO products (name, price, in_stock)
VALUES ('Mouse', 19.99, true);
💡
Columns you omit get their DEFAULT (or NULL). Listing column names — not relying on position — is the safe habit.

Bulk Inserting Many Rows at Once

Pass several comma-separated tuples in one statement. It’s far faster than one INSERT per row because it’s a single round-trip and transaction.

INSERT INTO products (name, price) VALUES
  ('Keyboard', 49.99),
  ('Monitor', 199.00),
  ('Webcam',   59.50);
INSERT 0 3
📌
The result tag INSERT 0 3 means “0 OID, 3 rows inserted.”

Update UPDATE — Changing Rows

UPDATE sets new column values for rows that match the WHERE clause.

UPDATE products
SET price = price * 1.10,        -- 10% price rise
    updated_at = now()
WHERE category = 'electronics';
⚠️
Forget the WHERE and you update EVERY row. Run a matching SELECT first to confirm which rows you’ll hit.

Delete DELETE — Removing Rows

DELETE removes rows matching WHERE. TRUNCATE wipes a whole table fast.

DELETE FROM products WHERE in_stock = false;

DELETE FROM products;       -- removes ALL rows (logged, slow)
TRUNCATE products;          -- removes ALL rows (fast, resets)
DELETE only touches rows the WHERE clause selects; the rest are untouched.
⚠️
Like UPDATE, a DELETE without WHERE empties the table. Wrap risky changes in a transaction (Part 14) so you can ROLLBACK.

Postgres power RETURNING — Get Data Back

A PostgreSQL superpower: RETURNING makes INSERT/UPDATE/DELETE hand back the affected rows — no second query needed.

INSERT INTO users (email, full_name)
VALUES ('a@x.com', 'Ada')
RETURNING id, created_at;

DELETE FROM cart WHERE user_id = 7 RETURNING *;
  id |          created_at
 ----+-------------------------------
  42 | 2026-06-30 09:15:02.31+00
💡
Perfect for grabbing the new auto-generated id right after inserting a row.

Insert-or-update Upsert with ON CONFLICT

“Insert, but if it already exists, update instead” — done atomically with ON CONFLICT.

INSERT INTO inventory (sku, qty)
VALUES ('ABC-1', 10)
ON CONFLICT (sku)
DO UPDATE SET qty = inventory.qty + EXCLUDED.qty;

-- or silently skip duplicates:
INSERT INTO tags (name) VALUES ('sql')
ON CONFLICT DO NOTHING;
📌
EXCLUDED refers to the row you tried to insert, so you can merge old and new values. Needs a UNIQUE/primary key on the conflict column.
