🔀 Set Ops & CASE Logic

Combine result sets and add conditional logic right inside your queries.

Stacking rows UNION & UNION ALL

Set operators stack the rows of two queries. UNION removes duplicates; UNION ALL keeps them (and is faster).

SELECT name, 'customer' AS kind FROM customers
UNION ALL
SELECT name, 'supplier' AS kind FROM suppliers
ORDER BY name;
Both queries’ rows are concatenated; UNION then removes duplicate rows.
💡
Use UNION ALL unless you specifically need duplicate removal — it avoids a costly sort/hash step.

Common & different INTERSECT & EXCEPT

INTERSECT returns rows in both queries; EXCEPT returns rows in the first but not the second.

-- users who are BOTH buyers and sellers:
SELECT user_id FROM buyers
INTERSECT
SELECT user_id FROM sellers;

-- users who bought but never sold:
SELECT user_id FROM buyers
EXCEPT
SELECT user_id FROM sellers;
📌
Think of them as set algebra: UNION = OR, INTERSECT = AND, EXCEPT = minus.

Requirements Set-Operation Rules

All set operations share strict rules:

  • Both queries must have the same number of columns.
  • Corresponding columns must have compatible types.
  • Column names come from the first query.
  • A single ORDER BY goes at the very end, applying to the whole result.
⚠️
Mismatched column counts or incompatible types raise an error. Add ALL (INTERSECT ALL, EXCEPT ALL) to keep duplicates.

If/else in SQL CASE Expressions

CASE is SQL’s conditional. It returns a value based on the first matching WHEN — usable anywhere an expression is allowed.

SELECT name, price,
  CASE
    WHEN price >= 200 THEN 'premium'
    WHEN price >= 50  THEN 'standard'
    ELSE 'budget'
  END AS tier
FROM products;

-- CASE inside an aggregate (conditional count):
SELECT COUNT(*) FILTER (WHERE price >= 200) AS premium_count
FROM products;
💡
CASE in ORDER BY enables custom sort orders; in SUM(CASE WHEN ...) it builds pivot-style conditional aggregates.

Handling NULLs COALESCE & NULLIF

Two essential NULL helpers:

  • COALESCE(a, b, c) — returns the first non-NULL argument.
  • NULLIF(a, b) — returns NULL if a = b, else a (handy to avoid divide-by-zero).
SELECT
  COALESCE(nickname, full_name, 'Anonymous') AS display,
  revenue / NULLIF(orders, 0) AS avg_order   -- no div-by-zero error
FROM accounts;
📌
NULLIF(orders,0) turns a 0 denominator into NULL, so the division yields NULL instead of erroring.

Changing types Casting & Type Conversion

Convert between types with CAST(x AS type) or the Postgres shorthand x::type.

SELECT '42'::integer + 8            AS num,      -- 50
       price::text || ' USD'        AS label,
       now()::date                  AS today,
       CAST('2026-06-30' AS date)   AS d;
💡
The :: cast is idiomatic Postgres. Casting also matters in set ops when one side is integer and the other numeric.
