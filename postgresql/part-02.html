🏗️ Creating Databases & Tables

Design a schema: pick data types and define tables with CREATE TABLE.

Setup Creating & Dropping Databases

A PostgreSQL server hosts many databases. Each database is isolated and holds its own tables.

CREATE DATABASE shop;
DROP DATABASE shop;            -- delete it (irreversible!)
DROP DATABASE IF EXISTS shop;  -- no error if it doesn't exist
createdb shop      # shell shortcut
psql -d shop       # connect to it
⚠️
DROP DATABASE permanently deletes everything inside. There is no undo — back up first.

Reference Core Data Types

Every column has a type that controls what it can store. Choosing well keeps data valid and storage efficient.

CategoryTypeUse for
Integerinteger, bigintwhole numbers, counts
Decimalnumeric(p,s)money, exact values
Floatreal, double precisionscientific/approximate
Texttext, varchar(n)strings
Booleanbooleantrue / false
Date/Timedate, timestamptzdates and moments
JSONjsonbstructured documents
UUIDuuidglobally unique IDs
💡
Prefer text over varchar(n) unless you truly need a length limit — they perform the same in Postgres.

Core CREATE TABLE

Define a table by listing its columns and their types. Each column can carry constraints that enforce rules.

CREATE TABLE users (
    id         serial PRIMARY KEY,
    email      text UNIQUE NOT NULL,
    full_name  text NOT NULL,
    age        integer CHECK (age >= 0),
    is_active  boolean DEFAULT true,
    created_at timestamptz DEFAULT now()
);
Each column = a name, a type, and zero or more constraints that guard your data.
📌
\d users in psql shows the table’s columns, types and constraints after you create it.

Constraints Defaults & NOT NULL

Two everyday constraints shape how columns behave when you insert rows.

  • NOT NULL — the column must always have a value; NULL is rejected.
  • DEFAULT expr — if you omit the column on insert, Postgres fills in expr.
CREATE TABLE posts (
    id        serial PRIMARY KEY,
    title     text NOT NULL,
    views     integer NOT NULL DEFAULT 0,
    published boolean DEFAULT false
);

-- title is required; views & published get defaults:
INSERT INTO posts (title) VALUES ('Hello');
💡
now(), true, or a literal like 0 all work as defaults. Defaults are evaluated per row at insert time.

Keys Auto-Incrementing IDs

Most tables need a unique surrogate key. PostgreSQL offers serial (classic) and GENERATED AS IDENTITY (modern SQL standard).

serial (simple)

CREATE TABLE t (
  id serial PRIMARY KEY,
  name text
);

identity (recommended)

CREATE TABLE t (
  id integer GENERATED ALWAYS
       AS IDENTITY PRIMARY KEY,
  name text
);
📌
serial auto-creates a hidden sequence and is fine everywhere. GENERATED ... IDENTITY is the newer, standards-compliant choice.

Evolving schema Changing Tables: ALTER & DROP

Schemas change. ALTER TABLE modifies an existing table without losing data; DROP TABLE removes it entirely.

ALTER TABLE users ADD COLUMN phone text;
ALTER TABLE users ALTER COLUMN phone SET NOT NULL;
ALTER TABLE users RENAME COLUMN full_name TO name;
ALTER TABLE users DROP COLUMN age;

DROP TABLE IF EXISTS posts;
⚠️
Adding a NOT NULL column to a table that already has rows fails unless you provide a DEFAULT or backfill values first.
