📡 Real-Time Apps with Socket.IO

Push data to clients the instant it changes — chats, notifications, live dashboards.

Concept HTTP vs WebSockets

Normal HTTP is one-way and short-lived: the client asks, the server answers, the connection closes. WebSockets keep a single connection open for two-way, instant messaging.

A WebSocket is a persistent, full-duplex pipe — either side can send at any time.
HTTPWebSocket
DirectionClient → ServerBoth ways
ConnectionOpens per requestStays open
Best forCRUD APIsChat, live updates, games
📌
Socket.IO wraps WebSockets with reconnection, rooms and fallbacks, making real-time easy and reliable.

Setup Socket.IO Setup

Attach Socket.IO to the same HTTP server your Express app uses:

npm install socket.io
// server.js
const http = require("http");
const { Server } = require("socket.io");
const app = require("./src/app");

const server = http.createServer(app);
const io = new Server(server, { cors: { origin: "*" } });

io.on("connection", (socket) => {
  console.log("Client connected:", socket.id);

  socket.on("disconnect", () => console.log("Client left:", socket.id));
});

server.listen(3000, () => console.log("Real-time server on :3000"));
📌
Each connected client gets a unique socket with an id. The io object represents all clients.

Hands-on Emitting & Listening

Communication is event-based — you emit named events and on them, just like EventEmitter, but across the network.

io.on("connection", (socket) => {
  // listen for a message from THIS client
  socket.on("chat:message", (text) => {
    // send it to EVERYONE (including sender)
    io.emit("chat:message", { id: socket.id, text });
  });

  // send to everyone EXCEPT the sender
  socket.broadcast.emit("user:joined", socket.id);

  // send only to this client
  socket.emit("welcome", "Hello from server");
});
CallSends to
socket.emit()Just this client
io.emit()All clients
socket.broadcast.emit()All except sender
io.to(room).emit()Everyone in a room

Pattern Rooms & Broadcasting

Rooms group sockets so you can target a subset — perfect for chat channels, game lobbies or per-user notifications.

io.on("connection", (socket) => {
  socket.on("room:join", (roomId) => {
    socket.join(roomId);
    socket.to(roomId).emit("system", "A new user joined");
  });

  socket.on("room:message", ({ roomId, text }) => {
    io.to(roomId).emit("room:message", { from: socket.id, text });
  });
});
💡
Join a room named after the user's id (socket.join(userId)) to push private notifications to just that person.

Hands-on The Client Side

In the browser, the Socket.IO client connects and uses the same emit/on API:

<script src="https://cdn.socket.io/4.7.5/socket.io.min.js"></script>
<script>
  const socket = io("http://localhost:3000");

  socket.on("connect", () => console.log("connected", socket.id));

  // receive messages
  socket.on("chat:message", (msg) => console.log(msg.text));

  // send a message
  document.querySelector("#send").onclick = () => {
    socket.emit("chat:message", "Hello everyone!");
  };
</script>
⚠️
In production, lock down cors.origin to your real front-end and authenticate sockets (e.g. verify a JWT on connection).
