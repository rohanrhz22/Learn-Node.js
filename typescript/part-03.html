🔧 Functions & Annotations

Type parameters and return values, handle optional and default arguments, and describe function shapes.

Parameters & returns Typing Functions

Annotate each parameter and, optionally, the return type. The return type is usually inferred.

function add(a: number, b: number): number {
  return a + b;
}

// arrow function with annotations
const mul = (a: number, b: number): number => a * b;

// return type inferred as number — fine to omit
const sub = (a: number, b: number) => a - b;
💡
Always type parameters; let TypeScript infer the return type unless you want it documented or pinned for safety.

Flexible calls Optional & Default Parameters

Mark a parameter optional with ?, or give it a default value. Optional params become type | undefined.

function greet(name: string, title?: string): string {
  return title ? `${title} ${name}` : name;
}
greet("Lee");              // ✅ title omitted
greet("Lee", "Dr.");       // ✅

// default value — type inferred from it
function power(base: number, exp: number = 2) {
  return base ** exp;
}
power(5);                  // 25
⚠️
Optional (?) parameters must come after required ones. A defaulted parameter is effectively optional too.

Variable arguments Rest Parameters

Collect any number of trailing arguments into a typed array with ....

function sum(...nums: number[]): number {
  return nums.reduce((t, n) => t + n, 0);
}
sum(1, 2, 3, 4);           // 10

function tag(label: string, ...values: string[]) {
  return `${label}: ${values.join(", ")}`;
}
tag("colors", "red", "green");  // "colors: red, green"
📌
The rest parameter must be last and is always an array type — here number[] and string[].

void, never & unions Return Types

Return types document what a function produces — including “nothing” or “never”.

function logIt(x: string): void { console.log(x); }

function find(id: number): string | undefined {
  return id === 1 ? "Ada" : undefined;
}

function crash(): never { throw new Error("boom"); }

// explicit return type catches mistakes inside the body
function half(n: number): number {
  return n / 2;            // change to a string -> compile error
}
💡
Adding an explicit return type to exported functions makes errors point at the function, not the faraway call site.

Describing callables Function Types

You can type a variable or parameter as a function signature, e.g. for callbacks.

// a variable holding a function
let op: (a: number, b: number) => number;
op = (x, y) => x + y;      // params inferred from the type!

// callback parameter typed inline
function apply(
  values: number[],
  fn: (n: number) => number
): number[] {
  return values.map(fn);
}
apply([1, 2, 3], n => n * 10);   // [10, 20, 30]
A function type describes its parameter types and its return type — nothing else.
📌
When the function type is known, parameter types are contextually inferred — notice we didn’t annotate x, y above.

Multiple signatures Function Overloads

Overloads let one function accept different argument shapes with precise return types.

function len(x: string): number;
function len(x: any[]): number;
function len(x: string | any[]): number {
  return x.length;
}

len("hello");      // ✅ 5
len([1, 2, 3]);    // ✅ 3
// len(42);        // ❌ No overload matches this call
💡
Prefer a union parameter when possible; reach for overloads only when the return type depends on the argument type.
