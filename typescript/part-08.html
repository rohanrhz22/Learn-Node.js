🏛️ Classes in TypeScript

Add types, access control, abstract bases and interfaces to JavaScript classes.

Fields & constructor Typed Classes

TypeScript classes annotate their fields and constructor parameters.

class Point {
  x: number;
  y: number;

  constructor(x: number, y: number) {
    this.x = x;
    this.y = y;
  }

  distance(): number {
    return Math.hypot(this.x, this.y);
  }
}

const p = new Point(3, 4);
p.distance();   // 5
📌
Fields must be declared with their types. With strictPropertyInitialization on, every field must be assigned in the constructor (or marked optional/definite).

Visibility Access Modifiers

Control who can see each member with public, private and protected.

class Account {
  public owner: string;       // default — anywhere
  private balance: number;    // this class only
  protected id: number;       // this class + subclasses

  constructor(owner: string) {
    this.owner = owner;
    this.balance = 0;
    this.id = Math.random();
  }
  deposit(n: number) { this.balance += n; }
}
const a = new Account("Ada");
// a.balance;   // ❌ 'balance' is private

💡
TS private is compile-time. For true runtime privacy use JS #fields (#balance) — they’re enforced by the engine.

Shorthand Parameter Properties

Add a modifier to a constructor parameter and TypeScript declares and assigns the field for you.

class User {
  constructor(
    public name: string,
    private email: string,
    readonly id: number,
  ) {}
  // no separate field declarations or this.x = x needed!
}

const u = new User("Lee", "lee@mail.com", 1);
u.name;   // ✅ "Lee"
💡
Parameter properties remove boilerplate. The equivalent long form needs a field declaration plus an assignment for each parameter.

Controlled access Getters, Setters & readonly

Use get/set accessors for computed or validated properties, and readonly for immutables.

class Temperature {
  readonly unit = "C";
  constructor(private _celsius: number) {}

  get celsius() { return this._celsius; }
  set celsius(v: number) {
    if (v < -273.15) throw new Error("below absolute zero");
    this._celsius = v;
  }
  get fahrenheit() { return this._celsius * 9 / 5 + 32; }
}
📌
Accessors are used like properties (t.celsius = 20) but run code — ideal for validation or derived values like fahrenheit.

Shared blueprints Abstract Classes

An abstract class can’t be instantiated; it defines methods subclasses must implement.

abstract class Shape {
  abstract area(): number;        // no body — must override
  describe(): string {            // shared concrete method
    return `Area is ${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(private r: number) { super(); }
  area() { return Math.PI * this.r ** 2; }
}
// new Shape();   // ❌ Cannot create an instance of an abstract class
Abstract classes share common behaviour while forcing subclasses to fill in the specifics.
📌
Use abstract classes when subclasses share real implementation. If you only need a contract with no shared code, use an interface instead.

Contracts Implementing Interfaces

A class can implements one or more interfaces, promising to provide their members.

interface Serializable { toJSON(): string; }
interface Comparable<T> { compareTo(other: T): number; }

class Money implements Serializable, Comparable<Money> {
  constructor(public cents: number) {}
  toJSON() { return JSON.stringify({ cents: this.cents }); }
  compareTo(o: Money) { return this.cents - o.cents; }
}
💡
implements only checks the shape — it adds no code. A class can extend one base and implement many interfaces.
