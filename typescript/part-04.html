📐 Interfaces & Type Aliases

Name reusable object shapes, extend them, and choose between interface and type.

Describing shapes Interfaces

An interface names the shape of an object: which properties it has and their types.

interface User {
  id: number;
  name: string;
  email: string;
}

const u: User = {
  id: 1,
  name: "Ada",
  email: "ada@mail.com",
};
// missing 'email' -> ❌ Property 'email' is missing
📌
Interfaces describe structure. TypeScript uses structural typing — if an object has the right shape, it fits, regardless of how it was declared.

Naming any type Type Aliases

A type alias names any type — objects, unions, primitives, tuples and more.

type ID = number | string;          // union
type Point = { x: number; y: number }; // object
type Pair = [string, number];          // tuple
type Handler = (e: Event) => void;     // function

const id: ID = "abc";
const p: Point = { x: 1, y: 2 };
💡
Use a type alias whenever you want a name for a union, tuple or function type — things an interface can’t express directly.

Property modifiers Optional & readonly

Mark a property optional with ? or immutable with readonly.

interface Product {
  readonly sku: string;   // can't be reassigned
  name: string;
  discount?: number;      // may be absent
}

const p: Product = { sku: "A1", name: "Pen" };
p.name = "Pencil";        // ✅
// p.sku = "B2";          // ❌ Cannot assign to readonly 'sku'
p.discount;               // number | undefined
⚠️
readonly is a compile-time guarantee only — it prevents reassignment in TS but does not freeze the object at runtime. Use Object.freeze for that.

Composition Extending Shapes

Interfaces extends other interfaces; type aliases compose with intersection &.

interface Animal { name: string; }
interface Dog extends Animal {
  breed: string;
}
const d: Dog = { name: "Rex", breed: "Lab" };

// type alias version with intersection
type Animal2 = { name: string };
type Cat = Animal2 & { indoor: boolean };
const c: Cat = { name: "Mia", indoor: true };
Extension builds bigger shapes from smaller ones — a core way to model your domain.
📌
An interface can extend multiple interfaces: interface C extends A, B {}. Type aliases do the same with A & B.

// Declaration merging — only interfaces can reopen:
interface Window { myApp: string; }
interface Window { version: number; }
// Window now has both members
💡
Rule of thumb: use interface for object shapes and public APIs; use type for unions, tuples, and mapped/conditional types (Parts 12–13).

Dynamic keys Index Signatures

When keys aren’t known ahead of time, describe them with an index signature.

interface Scores {
  [player: string]: number;   // any string key -> number
}
const s: Scores = { ada: 10, lee: 8 };
s.newPlayer = 5;              // ✅ allowed

// Record<K, V> is the cleaner built-in equivalent:
type Scores2 = Record<string, number>;
📌
Prefer Record<string, number> (a utility type, Part 10) over a raw index signature — it reads better and is just as type-safe.
